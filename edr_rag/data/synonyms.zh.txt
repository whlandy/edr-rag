# EDR 领域中文同义/别名词表
#
# 格式：每行 `别名 => 规范词`，`#` 开头为注释，空行忽略。
# 检索时 expand_query 会把命中的别名替换成规范词，生成一个查询变体，
# 与原查询一起做 multi-query 召回后 RRF 融合。
#
# ============================ 维护规则（重要）============================
#
# 本词表**禁止**从评测集（eval/data/*.jsonl）的 paraphrases 反向抄写。
#
# P1-6 的原始实现正是这么做的：SYNONYMS 里 16 条别名逐条对应评测集里 3 个
# action 的同义改写，然后再用同一份评测集去调 RRF 权重。结果是评测指标只是
# 在验证「我们把答案抄进了代码」，对真实查询没有任何预测力。
#
# 正确的来源只有两个：
#   1. 产品自身的术语（UI 文案、手册目录、工单里用户的真实说法）
#   2. 通用中文 IT/安全运维口语（与具体产品无关的动词、状态词）
#
# 新增条目时问一句：这条别名如果不在评测集里，还成立吗？不成立就别加。
# tests/test_query_expansion.py::test_synonyms_not_derived_from_eval_set
# 会对着评测集做结构性检查。
#
# 客户现场可用 EDR_RAG_SYNONYMS 指向自己的词表文件覆盖本表。
# =======================================================================
